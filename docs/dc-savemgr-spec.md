# DC セーブマネージャ (仮称) 仕様案 — BBA で PC とつながる VMU 管理ソフト

状態 (2026-11-03): 「決めること」は**推奨案で確定**。段階 1・2 ができて Flycast で確認済み。段階 3 (BBA、読むだけ) は PC 上のテストまで。
どれも実機は未確認。次は実機での段階 3 の確認、そのあと段階 4 (書き込み)。
実装は `dc/savemgr/`、使い方は README の「Dreamcast 本体のセーブマネージャ」。

## 1. 目的

Dreamcast 本体で動く VMU (ビジュアルメモリ) のセーブ管理ソフト。

1. **本体だけで使える**: Dreamcast 本体 (BIOS) のメモリーカード画面と同じこと (一覧・コピー・削除) ができる。
2. **本体だけでもう一歩**: 本体にはない機能 (VMU 丸ごとコピー、整理、検査、中身の確認) を足す。
3. **BBA で PC とつながる**: VMU のセーブを PC へコピー (バックアップ)、PC から VMU へ書き戻し、
   PC の VMU Workbench で編集してそのまま本体の VMU へ戻す。

## 2. すでにあるものと、この仕様での位置付け

| もの | 場所 | 使い方 |
|---|---|---|
| VMU Workbench (PC 側エディタ。GUI / CLI / MCP) | `H:\DC\tools\vmu-workbench` | PC 側はこれを拡張する。VMU 形式の処理 (`src/vmu.js` `vms.js` `containers.js`) が正解の基準 |
| vmutransfer (VMU イメージ丸ごと転送 ROM) | `vmu-workbench/emu/vmutransfer` | dcload の `/pc/` 経由で 128KB を丸ごと読み書きするだけ。新ソフトはこれの後継 (同じ機能を含む) |
| dc_vmu.ps1 (PC から dump / restore / PS1 カード変換) | `dc-bba-tools/scripts/dc_vmu.ps1` | 新ソフトの dcload モードを呼ぶように差し替える |
| BBA 接続 | 直結ケーブル、PC 192.168.10.1 / DC 192.168.10.2 | 既定値としてそのまま使う |

注: vmu-workbench と dc-bba-tools には今日の作業の**未コミットの変更**がある (vmutransfer、dc_vmu.ps1 など)。この仕様書の追加以外は触っていない。

## 3. 全体構成

```
 ┌──────── Dreamcast ────────────────────────┐          ┌──────────── PC ─────────────────────┐
 │  セーブマネージャ (KallistiOS)              │          │  VMU Workbench                       │
 │   ├ 画面とパッド操作 (BIOS 相当 + 拡張)     │          │   ├ GUI: 「DC」ペイン (A1〜D2 を直接開く)│
 │   ├ VMU 処理 (C。ブロック単位・RAM 上で編集)│  BBA     │   ├ CLI: node cli.js dc ...           │
 │   ├ HTTP サーバ  :80   ◀───── PC から操作 ──┼──────────┤   ├ MCP: AI から dc_* ツール           │
 │   └ HTTP クライアント ───── DC から送る ───▶┼──────────┤   └ 受け口 + 保管庫 (serve.js :8765)   │
 │  (dcload で起動したときは /pc/ も使える)    │          │  dc-bba-tools: dc_vmu.ps1 / dc_auto   │
 └───────────────────────────────────────────┘          └─────────────────────────────────────┘
```

- **DC が HTTP サーバ**になり、PC はブラウザや VMU Workbench から DC の VMU を一覧・取得・書き込みする (PC 主導)。
- 本体のパッドから「PC へ送る」「PC の保管庫から取り込む」も使えるように、**DC は HTTP クライアント**にもなる
  (PC 側で VMU Workbench の受け口が動いているとき)。
- PC にソフトが何もなくても、DC が出す簡単な Web ページ (一覧・ダウンロード・アップロード) だけで最低限は使える。

## 4. 機能

### 4.1 本体 (BIOS) と同じ機能

| 機能 | 内容 |
|---|---|
| VMU の選択 | A1〜D2 の 8 か所。挿さっているものだけ表示。空きブロック数を表示 |
| ファイル一覧 | アイコン (アニメーション)、ファイル名、説明 (VMS ヘッダの 16 / 32 文字)、ブロック数、日付 |
| ファイル情報 | 上に加えてコピー禁止かどうか、ゲーム (ミニゲーム) かデータか |
| コピー | 別の VMU へ。コピー禁止のファイルはコピーしない (本体と同じ)。空きが足りなければ不可 |
| 削除 | 1 ファイル削除 (確認あり) |
| 全部消去 | VMU の初期化 (二重確認) |

ミニゲームはブロック 0 から連続して置く必要があり、1 個の VMU に 1 つだけ。この規則は本体と同じに守る。

### 4.2 本体にはない機能 (DC 単体)

| 機能 | 内容 |
|---|---|
| VMU 丸ごとコピー | ブロック単位で VMU → VMU (vmutransfer の X ボタンと同じ)。コピー先は事前に RAM へ退避 |
| 整理 (デフラグ) | 断片化したファイルを詰め直す。ミニゲームを入れる空きを作る |
| 検査 | FAT・ディレクトリ・VMS ヘッダ CRC の矛盾を表示 (`vmu.js check()` と同じ判定) |
| 中身の確認 | 16 進表示 (読むだけ)。後の段階でバイト編集 + CRC 自動更新 |
| 並べ替え | 一覧の表示順 (名前 / 日付 / サイズ)。ディレクトリ順の書き換えは任意 |
| bleem2 の PS1 カード | `BLEEMMC` の中の PS1 セーブ一覧を表示 (後の段階) |
| 取り消し | 直前の書き込みの前のイメージを RAM に持ち、1 回分は戻せる |

### 4.3 BBA 連携

**PC から操作 (DC は待ち受け画面のまま)**

| 機能 | 内容 |
|---|---|
| 一覧 | 全 VMU のファイル一覧 (JSON)。アイコンも生データで返し、PC 側で描く |
| PC へコピー | 1 ファイル (`.dci` / `.vmi + .vms` / 生データ) または VMU 丸ごと (`.bin` 128KB) |
| PC から書き込み | ファイル追加・上書き、VMU 丸ごと書き戻し |
| 削除・整理・初期化 | 4.1 / 4.2 と同じ操作を PC から |
| 編集して戻す | VMU Workbench で DC の VMU を開き、16 進・名前付き値・アイコンを編集 → 変わったブロックだけ書き戻す |
| 自動バックアップ | PC 側が接続のたびに全 VMU を保管庫へ保存 (同じ中身なら保存しない) |

**DC から操作 (パッドで)**

| 機能 | 内容 |
|---|---|
| PC へ送る | 選んだファイル / VMU 丸ごとを PC の保管庫へ |
| PC から取り込む | PC の保管庫の一覧を DC の画面に出し、選んで VMU へ書く |
| 全部バックアップ | 挿さっている全 VMU を一度に PC へ |

PC の保管庫の置き場: `<保管庫>/<VMU の識別名>/<日時>/image.bin` と各ファイルの `.dci`。
VMU の識別名はルートブロックのフォーマット日時から作る (VMU に固有の番号はないため)。DC の画面で名前を付けられる。

## 5. 画面と操作

```
┌ セーブマネージャ ─────────────── 192.168.10.2  PC:接続中 ┐
│ [A1] 128ブロック空き  [A2] --  [B1] 12ブロック空き  ...   │
├──────────────────────────────────────────────────┤
│ ▶ (icon) SONICADV_INT   ソニックアドベンチャー   10   2026/10/12 │
│   (icon) BLEEMMC        bleem! memory card       48   2026/11/03 │
│   ...                                                        │
├──────────────────────────────────────────────────┤
│ A:メニュー  B:戻る  X:PCへ送る  Y:VMU切替  L/R:並べ替え  START:設定 │
└──────────────────────────────────────────────────┘
```

- メニュー: コピー / 削除 / 情報 / 中身 / PC へ送る。VMU 側のメニュー: 丸ごとコピー / 整理 / 検査 / 全部消去 / PC から取り込む。
- PC から書き込み・削除・初期化の要求が来たら、DC の画面に内容を出して **A で許可・B で拒否**。
  設定で「PC からの操作をこの起動中は全部許可」にできる (自動化用)。
- VMU のアイコンは本体と同じく VMU の液晶にも出す (任意)。
- 文字は KOS の bfont (日本語も出る)。

## 6. 通信仕様 (DC の HTTP サーバ)

HTTP/1.1、ポート 80、JSON とバイナリ。認証なし (直結ケーブル前提。書き込みは DC 側の許可で守る)。
ブラウザから直接呼べるよう CORS を許可する。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/` | 簡易 Web ページ |
| GET | `/api/info` | ソフトの版、IP、各スロットの有無・空き・識別名・イメージの版 (ETag) |
| GET | `/api/vmu/{slot}` | ファイル一覧 (名前、種類、ブロック数、先頭ブロック、コピー禁止、日付、説明、アプリ ID、CRC 正否、アイコン枚数) |
| GET | `/api/vmu/{slot}/image` | 128KB イメージ。`ETag` = イメージの CRC32 |
| PUT | `/api/vmu/{slot}/image` | 丸ごと書き戻し。`If-Match` 必須 |
| GET | `/api/vmu/{slot}/file/{name}?fmt=dci\|raw` | 1 ファイル |
| PUT | `/api/vmu/{slot}/file/{name}` | 追加・上書き (`.dci` か、生データ + 種類・コピー禁止のヘッダ)。`If-Match` 必須 |
| DELETE | `/api/vmu/{slot}/file/{name}` | 削除。`If-Match` 必須 |
| PATCH | `/api/vmu/{slot}/blocks` | 変わったブロックだけ書く (編集の書き戻し用)。`If-Match` 必須 |
| POST | `/api/vmu/{slot}/copy` | `{ "to": "b1", "names": [...] }`、`names` 省略で丸ごと |
| POST | `/api/vmu/{slot}/defrag` / `format` | 整理 / 初期化 |
| GET | `/api/events` | VMU の抜き差し・書き込み完了を待つ (ロングポーリング) |

- `slot` は `a1`〜`d2`。`If-Match` が今の ETag と違えば 412 (VMU を差し替えた・本体側で変えた、を検出)。
- DC の許可待ちの間は 202 を返し、PC は `/api/events` で結果を待つ。拒否は 403。
- **DC → PC (DC から送るとき)**: `POST http://<PC>:8765/dc/backup` (VMU Workbench の受け口)、`GET /dc/library` で保管庫の一覧。
- PC から DC を探す: UDP 同報 (ポート 8766) に DC が IP と版を返す (後の段階)。
- **dcload モード**: dcload-ip から起動したときは KOS の `fs_dclsocket` で dcload と BBA を共有し、HTTP に加えて
  `/pc/` へ直接読み書きできる。dc_vmu.ps1 の命令ファイル (`vmu_cmd` → `vmu_result.txt`) もこのモードで受ける。

## 7. PC 側 (VMU Workbench の拡張)

| 追加 | 内容 |
|---|---|
| `src/dcclient.js` | 上の API を呼ぶ部品。GUI・CLI・MCP で共用 |
| GUI「DC」ペイン | IP を入れて接続 → A1〜D2 を A/B ペインと同じ見た目で開く。ファイル単位のドラッグでコピー、編集後「DC へ書き込み」 |
| CLI | `dc info` / `dc list a1` / `dc pull a1 [NAME] out` / `dc push a1 file.dci` / `dc backup` / `dc restore a1 image.bin` |
| MCP | `dc_list` / `dc_pull` / `dc_push` (書き込みは DC 側の許可が必要なのは同じ) |
| serve.js | 受け口 `/dc/backup` と保管庫 `/dc/library`。GUI から DC への通信を中継 (ブラウザの制限を避ける) |
| dc_vmu.ps1 | `-Dump` / `-Restore` を新ソフトに向ける。HTTP があれば dcload なしでも動く |

PC 側でも書き込みの前に必ず DC の今のイメージを `history` に保存する (今の dc_vmu.ps1 と同じ考え)。

## 8. 安全のための決まり

1. **書き込みは RAM 上で組み立ててから**: VMU を 128KB 丸ごと読み、RAM 上で変更し、変わったブロックだけ書く。
   KOS の vmufs は使わない (ファイル単位の API では丸ごとコピー・整理・検査ができず、挙動も読みにくい)。
2. **書く順番**: データ → FAT → ディレクトリ → ルート。途中で抜かれても「新しいデータが使われないだけ」になりやすい順。
3. **書いたら読み直して確かめる** (vmutransfer と同じ)。合わなければ 3 回まで書き直し、だめなら退避イメージを表示して止まる。
4. **書く前に退避**: 書く前のイメージを RAM に 1 つ (取り消し用)。PC につながっていれば PC にも送る。
5. **差し替え検出**: 書く直前にルートブロックを読み直し、識別名が変わっていれば中止。PC からは ETag で同じことをする。
6. **コピー禁止のファイル**: 本体と同じく VMU → VMU のコピーはしない。PC へのバックアップと戻しは許可 (「決めること」参照)。
7. **書き込み中は抜かないで、を画面に出す**。進み具合をブロック数で表示。

## 9. VMU 形式 (実装で守る点)

- 128KB = 512 バイト × 256 ブロック。255 ルート、254 FAT、253〜241 ディレクトリ (13 ブロック、1 件 32 バイト)、0〜199 ユーザー領域。
- ディレクトリ 1 件: 種類 (0x33 データ / 0xCC ゲーム / 0x00 空き)、コピー禁止 (0xFF)、先頭ブロック、名前 12 バイト、
  BCD 日付 8 バイト、ブロック数、ヘッダ位置 (ゲームは 1、データは 0)。
- VMS ヘッダ: 説明 16 + 32 バイト、アプリ ID、アイコン枚数、アニメ速度、アイキャッチ、CRC、データ長、パレット、アイコン 512 バイト × 枚数。
- 書いたファイルの日付は DC の時計から付ける (PC から来たファイルは元の日付を残すか選べる)。
- 判定と書き込みの結果は `src/vmu.js` と一致させる: **同じイメージに同じ操作をしたら、JS 版と C 版で同じ 128KB になる**ことをテストで確かめる。

## 12. 決めること (推奨案つき)

| # | 項目 | 推奨 | 他の案 |
|---|---|---|---|
| 1 | 通信のやり方 | **DC が HTTP サーバ + DC から送るときは HTTP クライアント** (単体起動で使える、ブラウザでも使える) | dcload の `/pc/` だけ (簡単だが毎回 dc-tool-ip が必要、GDEMU 単体では使えない) |
| 2 | IP の決め方 | **既定 192.168.10.2 固定 (DHCP しない)**。設定画面で変更・DHCP に切替 | 本体のフラッシュの ISP 設定を読む |
| 3 | コピー禁止ファイル | **VMU → VMU は本体どおり禁止、PC へのバックアップと戻しは許可** | すべて本体どおり禁止 / すべて許可 |
| 4 | PC からの書き込み | **毎回 DC で A 許可 (起動中だけ「全部許可」に切替可)** | 確認なし (自動化しやすいが誤操作に弱い) |
| 5 | DC 上での編集 | **最初は 16 進表示だけ。編集は PC (VMU Workbench) で** | DC でもバイト編集・名前付き値の編集 |
| 6 | 設定の保存先 | **保存しない (毎回既定値。変えたいときは CDI に設定ファイルを入れて作り直す)** | VMU に小さい設定ファイル (1 ブロック使う) |
